Lab 09: Structures and Files

Electrical Mechanical & Materials
Date Tue Oct 13, 2026 Wed Oct 21, 2026
Time 2:00–4:00 pm 2:00–4:00 pm

Lab pack: lab09.tar.gz. It is already on the lab machines. You can also download it to practise at home.

Syllabus practical modules: 4 and 8 — records, and file handling.

Evaluation: This lab is graded, with the same weight as the others inside the 20% lab component. It is marked in three tiers:

Each Total
Write drills w01–w10 one line of C each 1 10
Blanks b1–b5 one loop or line each 5 25
Problems e1–e4 specification only 10 40

That is 75 marks from the programs. The remaining 25 come from observed work and a short viva, in which you will be asked to explain your own code.

The read drills (./drill.sh) are not marked.

You may work in teams of one or two. If you are a pair, swap who types at the halfway point.

This lab follows the Week 11 lectures: Monday on structures, Tuesday on files. The Week 11 notes contain everything you need. Problem e1 is the point-in-rectangle problem worked through in Monday’s lecture.

The shape of this lab

One idea, carried through three stages:

a record is several values under one name → many records in an array, and questions you can ask of the whole set → the records come from a file, and your answers go back into one

The write drills build the notation, the blanks use it on an array of records, and the last two problems replace the keyboard with a file.

Every starter file has a BEFORE line naming the drills it rests on. If you are stuck, that line tells you what to go and do first.

The minimum C you need today

Everything in this lab is built from these lines.

struct Student {             /* a type: several values under one name     */
    int    roll;
    char   name[20];
    double cgpa;
};

struct Student s;            /* now a variable of that type               */
s.roll = 1001;               /* reach a member with a dot                 */
scanf("%d %19s %lf", &s.roll, s.name, &s.cgpa);   /* note: no & on name   */

struct Student a[32];        /* an array of records                       */
a[i].cgpa                    /* index first, then member                  */

struct Student *p = &s;      /* a pointer to a record                     */
p->cgpa                      /* which uses -> instead of .                */

FILE *f = fopen("students.txt", "r");       /* open for reading           */
if (f == NULL) { ... }                      /* ALWAYS check this          */
while (fscanf(f, "%d %19s %lf", &r, nm, &c) == 3) { ... }   /* to the end */
fclose(f);

Three places where almost all the mistakes happen:

&s.roll has an &, s.name does not. Both are members of the same structure in the same scanf. The difference is that name is an array, and an array name is already an address. Drills w10 and b1 are about exactly this.

A double is read with %lf, not %f. %f is for printing a double, and for reading a float. Handing scanf a %f with the address of a double is undefined behaviour — it is not that you get a wrong number, it is that the standard says nothing at all about what happens, and in practice it writes four bytes into an eight-byte variable and leaves the rest as it was. Use %lf to read, %f to print.

Compare programme codes with strcmp, never with ==. a == b on two character arrays compares addresses, which are never equal, so the test is silently always false.

Act 1 · Read drills (20 minutes, not marked)

./drill.sh --all

Fifteen short programs. For each one you type what you think it will print, and only then does it run.

Drills What they are about
d01–d03 what a structure is, and what b = a does
d04–d05 by value against by address — the same function, twice
d06–d08 arrays of records, ->, and a structure inside a structure
d09 sizeof a structure, and why it is not the sum of its parts
d10 comparing programme codes with strcmp
d11–d12 fopen when the file is not there; what "w" does to one that is
d13–d14 what fscanf returns, and whether the line layout matters
d15 why while (!feof(f)) is wrong

d11–d15 are the ones to do carefully. e3 and e4 are worth 20 marks between them and both stand on exactly these five facts.

These carry no marks. A wrong prediction costs you nothing, which is exactly why you should write it down before pressing Enter.

Act 2 · Write drills (20 minutes, 1 mark each)

Ten files, w01.c to w10.c. In each one, everything is written except a single line, and the comment tells you what that line must do.

What you write Clue
w01 read two numbers straight into the members of a structure &p.x is the address of the member, not of p
w02 read members of two different types a double is read with %lf. %f there is undefined behaviour, not a near miss
w03 copy a structure, change the copy, leave the original alone two lines: the first copies, the second changes the copy
w04 a function body that gets a structure by value write it, run it, watch nothing happen — that is the result
w05 the same, but by address — compare the two p is a pointer, so the member is spelt p->x
w06 read three records into an array &a[i].x — index first, then member, then take the address
w07 reach members through a pointer, with -> aim q at p first; no & in the printf
w08 read into a structure that holds two other structures four addresses, two levels deep: &r.lo.x, &r.lo.y, &r.hi.x, &r.hi.y
w09 find the largest member in an array of records keep the index of the best, not the value
w10 read a name and a programme code no & on s.name — an array is already an address. Bound both: %19s, %7s

w04 and w05 are a matched pair. Do them one after the other: the first cannot change the caller’s record and the second can, and that is the whole lesson.

How to work on one problem

The steps are the same for all nineteen. Using w01.c as the example:

vim w01.c                # open it and write the missing line
gcc w01.c -o w01         # compile it
./w01 < w01_sample.txt   # run it on the sample input
./check.sh w01           # once it runs, have it marked

Plain gcc. No -lm, no other flags.

Every problem has a ready-made input file, named <problem>_sample.txt, and each one reproduces the EXAMPLE printed at the top of that starter:

$ ./w01 < w01_sample.txt
x=3 y=4
$ ./b5_topper < b5_sample.txt
topper=1002

Compile and run it yourself before running ./check.sh. Running it shows you what your program does; the checker only tells you whether the answer is right.

Act 3 · Blanks (25 minutes, 5 marks each)

Everything around the gap is written for you. Write the missing loop or line.

File What it must do Ends with Clue
b1_make.c build one complete record and print it back <roll> <name> <cgpa> one scanf, three conversions. & on roll and cgpa, none on name. Print with %.2f
b2_arrow.c the same record, reached through a pointer roll=<R> cgpa=<C> use p, not s. &p->roll works because -> binds tighter than &
b3_average.c the average cgpa over an array of records average=<A> one loop to add, then one printf. total is a double, so the division is real
b4_above.c how many records are strictly above 7.00 above=<N> > and not >=. One test case is three students at exactly 7.00, expecting above=0
b5_topper.c the roll of the record with the highest cgpa topper=<R> the index again, as in w09. > keeps the earlier student on a tie; >= would not

b4 and b5 both turn on one character. Strictly above means > 7.0, so a cgpa of exactly 7.00 does not count — one of the test cases is three students at exactly 7.00 and expects above=0. In b5, a tie goes to the first of the tied students, which you get for free by testing with > and not >=.

Act 4 · Problems (40 minutes, 10 marks each)

Specification only. You write the whole program.

Problem What it must do Its last line must end with
e1.c is a point inside a rectangle? inside or outside
e2.c the topper, from a list of records topper=<roll> <name>
e3.c reads students.txt — which programme has the most students above 7 program=<code> count=<N>
e4.c reads students.txt, writes passed.txt passed=<N>

Each of the four has a shape below: the skeleton, with the thinking left to you. Fill in the ....

e1 — the shape

Monday’s lecture problem. Name things so the conditions read like the maths.

struct Point { int x, y; };
struct Rect  { struct Point lo, hi; };

int inside(struct Rect r, struct Point p)
{
    return  ... four comparisons joined by && ... ;
}

int main(void) {
    struct Rect  r;
    struct Point p;
    scanf(...);                  /* the four corner numbers, into r.lo and r.hi */
    scanf(...);                  /* the point, into p                           */
    if (inside(r, p)) printf("inside\n");
    else              printf("outside\n");
}

r.lo.x is two steps: r.lo is a Point, .x is the int in it. Both structures go in by value — nothing is modified and six ints is nothing to copy, so no & and no * anywhere. A point exactly on an edge counts as inside, and two test cases sit on the boundary to check you meant >= and not >.

e2 — the shape

b5 with more to report.

struct Student { int roll; char name[20]; char program[8]; double cgpa; };

int main(void) {
    struct Student a[64];
    int n, i, best = 0;

    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf(...);              /* one scanf, all four members of a[i] */
    for (i = 1; i < n; i++)
        if (...) best = i;       /* compare against a[best]             */
    printf("topper=%d %s\n", ..., ...);
}

Keep the index of the best, not a copy of the cgpa — you owe two facts about that student and a number alone cannot tell you the name. Start best = 0 and begin the second loop at i = 1: the first student leads until someone beats them. Test with >, so a tie keeps the earlier one.

e3 and e4 do not read the keyboard

These two read the file students.txt, which is already in your workspace. Run them with no input at all:

gcc e3.c -o e3
./e3

Each line of students.txt holds one record:

1001 Ravi EE 8.20
1002 Asha ME 6.50
1003 Iqbal EE 7.10
WarningEvery name in this lab is a single word, and that is a simplification

Real names are not like this. Ravi Kumar, Subrahmanyan Chandrasekhar, A R Rahman — most of the names in this room have a space in them. We have excluded them on purpose, so that %19s works and today can be about records and files rather than about parsing text.

Be clear about what the simplification costs, because it is not a small thing. fscanf(f, "%d %19s %7s %lf", …) on the line

1001 Ravi Kumar EE 8.20

does not read Ravi Kumar. %19s stops at the space, takes Ravi, hands Kumar to the %7s and EE to the %lf, which fails — so the call returns 3, not 4, your loop ends, and the rest of the file is silently ignored. No error, no crash, just a shorter answer than the data deserved.

So: the code you write today is correct for the data you are given and wrong for the world. That is a normal and acceptable position for a teaching exercise, as long as you know which of the two you are in. When you need the real thing, the Week 11 appendix shows how — a separator the data cannot contain, or reading the line and splitting it yourself.

and the file ends when it ends — you are not told in advance how many lines there are. That is what this pattern is for:

while (fscanf(f, "%d %19s %7s %lf", &roll, name, prog, &cgpa) == 4) {
    ...
}

It stops as soon as a read does not deliver all four items, which is what happens at the end of the file.

e3 — the shape

No array of records at all — you never store a student.

char PROG[3][4] = { "EE", "ME", "MM" };
int  count[3]   = { 0, 0, 0 };        /* how many above 7.00        */
int  firstAt[3] = { -1, -1, -1 };     /* the row each FIRST appeared */
int  row = 0;

/* read one record at a time; for each one:
       find which of the three programmes it is   (strcmp against PROG[i])
       if this is its first sighting, note the row
       if the cgpa is above 7.00, add one to its count
       row++
   then walk i = 1, 2 and keep the better of count[i] and count[best]  */

Six small variables and a row counter do the whole job. -1 means not seen yet — do not use a value that could be a row, like 999, because a long enough file would reach it. A programme can appear with nobody above 7.00; it still appeared, so its firstAt must still be set. On a tie the smaller firstAt wins, and a programme never seen loses to one that was.

e4 — the shape

You have two files open at once, so give them two names that say which is which. f and g will cost you an hour.

int main(void) {
    FILE *in_file  = fopen("students.txt", "r");
    FILE *out_file = fopen("passed.txt",   "w");
    struct Student s;
    int passed = 0;

    if (in_file  == NULL) { ... report, return 1 ... }
    if (out_file == NULL) { ... report, return 1 ... }

    while (fscanf(in_file, ...) == 4) {
        if ( ... above 7.00 ... ) {
            fprintf(out_file, "%d\n", s.roll);
            passed++;
        }
    }

    fclose(in_file);
    fclose(out_file);
    printf("passed=%d\n", passed);
}

fscanf reads from in_file; fprintf writes to out_file. Each takes its file as the first argument, and if you swap them the compiler will not stop you — the data will simply go nowhere. Check both fopens: the input can be missing, and the output can fail too, on a full or read-only disk. fclose(out_file) is not optional: what you wrote may still be in a buffer, and the checker reads the file after your program exits. This is e3’s loop with two extra lines in it, so get e3 right first. And nobody qualifying is a valid answer — passed.txt exists, is empty, and you print passed=0.

e4 is graded twice: the line you print and the contents of passed.txt. A correct count on screen earns nothing if the file was never written. The checker deletes any old passed.txt before each test, so a file left over from an earlier run cannot be mistaken for this one.

How the checking works

./check.sh e1 compiles your source and runs it on two kinds of input: a fixed set chosen in advance, labelled public, and a set generated fresh at that moment from the range in the GIVEN line, labelled random. A program that only reproduces the printed example will fail as soon as a new input is drawn.

For e3 and e4 the checker writes a fresh students.txt before each test and gives your program an empty keyboard input. A leftover scanf will not hang: it finds no input, returns EOF, and leaves your variable holding whatever it held before. So the symptom is a wrong answer from a program that looked like it ran fine — which is exactly why you should check what scanf returned rather than assume it worked.

Act 5 · Check your marks, fix, and submit (10 minutes)

./check.sh          # everything
./check.sh e3       # one problem, while you are working on it

Marks are given per test case, not all-or-nothing, so fixing a failing case is worth doing even in the last few minutes. Two caveats, so the number does not surprise you:

  • Each problem’s mark is rounded to a whole number. A write drill is worth 1 mark over 5 cases, so passing 2 of 5 rounds to 0 and 3 of 5 rounds to 1. On the 10-mark problems every case really does carry its own share.
  • Some cases are drawn fresh each run, so the total can move by a mark or two between checks. Treat it as an estimate.

When you are finished, or when time is called:

./check.sh --bundle

The bundle is written to the directory above your workspace, named lab09_<rolls>_<branch>_w<NN>.tar.gz. Take it with you: upload it to Moodle and email a copy to yourself. The lab machines are wiped between sessions.

If you finish early (not marked)

  1. Make e3 report the programme with the highest average cgpa instead of the most students above 7. Which parts of the loop change, and which do not?
  2. Make e4 write the name next to each roll, and check it. Then undo that and make it write a header line first, and check that. The checker rejects both — read its two complaints and work out which line of passed.txt it is objecting to in each case.
  3. Add a struct Rect function int overlap(struct Rect a, struct Rect b) that says whether two rectangles overlap at all. Start from e1: two rectangles miss each other exactly when one is entirely to one side of the other.

  2. In e3, why strcmp and not ==?
  3. What would your e4 do if students.txt were not there? Did you try it?
