Lab 10: Dynamic Memory and Recursion

Electrical Mechanical & Materials
Date Tue Oct 27, 2026 Wed Oct 28, 2026
Time 2:00–4:00 pm 2:00–4:00 pm

Syllabus practical module: 5 — pointers, dynamic memory and recursion

Evaluation: Graded — equal weight within the 20% lab component.

Lab manual: The C Programming Laboratory — the department’s shared reference (vim §1 · the compilation model §2.5 · types and #define §2.7–2.8 · the operator precedence table §2.9–2.10 · printf/scanf §3). This sheet is self-contained; the manual is there when you want more.

Lab pack: lab10.tar.gz.

What you will practise

One common lab for EE / ME / MT: half dynamic memory allocation and half recursion. Read code and predict its behaviour, complete missing parts, then write complete functions. The W13 notes contain runnable examples.

Component Allocation Recursion Marks
Read drills d01–d05 d06–d10 Practice, unmarked
Write drills w01–w04 w05–w08 8 × 1 = 8
FIBs b1–b2 b3–b4 4 × 6 = 24
Exercises e1–e2 e3–e4 4 × 12 = 48
Explanation/source review 10 marks 10 marks 20
Total 50 50 100

Work alone or in a pair. Swap who types halfway; both members must be able to explain both topics. A member who cannot explain their code must resubmit solo.

Pre-lab: the C you need

Use <stdlib.h> for allocation, <string.h> for strlen and strcpy, and <stdio.h> for input/output. The starters include these headers.

Construct Meaning and caution
int *p = malloc(n * sizeof *p); Reserve n ints. Check for NULL, then initialise elements before reading.
int *p = calloc(n, sizeof *p); Reserve n ints initially equal to zero. Still check and later free.
int *tmp = realloc(p, new_n * sizeof *p); For a positive size, failure leaves p valid. On success use tmp; old pointer values must no longer be used. Initialise added elements.
free(p); p = NULL; Release once, then reset this pointer. Other aliases are not repaired.
malloc(strlen(source) + 1) Reserve characters plus the terminating null character.
p[i].value and p->value Access a structure-array element or the first pointed-to structure.
int result = f(smaller_argument); Suspend this call, collect the recursive result, then continue.

A recursive function needs a base case, progress towards it, and the correct returned result. Every call has its own parameters and locals; an array argument still refers to shared data. Recursion is required where specified; a loop producing the same output does not fulfil that requirement.

Use the memory explorer and recursion explorer to rehearse the concepts. These follow Prof. Shweta Agrawal’s CS1100 lectures, IIT Madras, used with permission.

Get started

Download and extract the pack if it is not already on your machine:

wget https://acads-iit-jammu.github.io/csp-f26-dhavala/labs/lab10.tar.gz
tar xzf lab10.tar.gz
cd lab10
./install.sh

The installer creates your workspace and opens it with a [lab10 OK ...] prompt. At home, supply --branch ee, --branch me or --branch mt if needed. Use ./where.sh if you lose your place. Reinstallation preserves your edited files. Start the transcript inside the workspace:

script session.txt

Read drills: comprehension

./drill.sh --all

Predict the output before running each program. These drills are unmarked.

ID Focus
d01 Allocated array, initialisation and pointer access
d02 Integer values after calloc and an update
d03 Two pointers to one allocation
d04 Preserved values after a successful resize
d05 Cleanup after a deliberately simulated failed resize
d06 Statements before and after a recursive call
d07 Factorial, including zero
d08 Each invocation’s own local variables
d09 Maximum of a shorter prefix
d10 Repeated calls in Fibonacci

For discussion: why can we not predict an output from reading freed storage? Why does assigning NULL to one pointer not repair its aliases? Do not run invalid memory operations to discover an answer.

How to work on the marked tasks

Every starter contains its GIVEN, TASK, input contract and BEFORE prerequisites. Edit only the numbered TODO regions, retaining the signatures and supplied driver. A TODO may contain several statements; there is no line-count restriction. Remove its #error directive when you complete it. Unfinished starters deliberately do not compile. Write drills need a small addition; FIBs complete parts of an algorithm; exercises require complete function bodies.

vim b1.c
gcc -std=c11 -Wall -Wextra -Wpedantic b1.c -o b1
./b1 < b1_sample.txt
cat b1_expected.txt
./check.sh b1

Every task has a separate sample-input and expected-output file. Inputs meet the stated bounds; invalid-input parsing is not part of this lab. Do not add prompts. On allocation failure follow the specified function contract; supplied drivers print allocation-failed and return 1. Regular output tests assume allocation success, but failure handling and cleanup remain part of source review.

Write drills: focused additions

w01 — Allocate an integer array

Before: d01. Topic: allocation.

Given: n in 1..20; value in -100..100. Input: n value.

Allocate n ints using malloc and sizeof *p.

Sample input (w01_sample.txt):

3 7

Expected output:

first=7 last=7

w02 — Check the pointer

Before: d05. Topic: allocation.

Given: flag is 0 or 1; value in -100..100. Input: flag value.

Return -1 if p is NULL; otherwise return *p. The driver simulates the two possible pointer states without trying to exhaust memory.

Sample input (w02_sample.txt):

0 9

Expected output:

result=-1

w03 — Initialise allocated elements

Before: d01 d02 w01. Topic: allocation.

Given: n in 1..20; start in -100..100. Input: n start.

Set p[i] to start + i for every valid index.

Sample input (w03_sample.txt):

4 -2

Expected output:

values: -2 -1 0 1

w04 — Release and reset

Before: d03 d05. Topic: allocation.

Given: value in -100..100. Input: value.

Release the allocation once, then set p to NULL.

Sample input (w04_sample.txt):

7

Expected output:

value=7
reset=1

w05 — Factorial base case

Before: d07. Topic: recursion.

Given: n in 0..12. Input: n.

Complete the base case, including 0!.

Sample input (w05_sample.txt):

5

Expected output:

factorial=120

w06 — Progress towards the base case

Before: d06. Topic: recursion.

Given: n in 0..20. Input: n.

Return 1 + … + n recursively; sum_to(0) is 0.

Sample input (w06_sample.txt):

4

Expected output:

sum=10

w07 — Capture the recursive result

Before: d09. Topic: recursion.

Given: n in 1..20, then n integers in -100..100.

Find the maximum recursively. maxOfPrefix must hold the maximum of the first n-1 elements.

Sample input (w07_sample.txt):

4 -4 -2 -9 -1

Expected output:

maximum=-1

w08 — Combine two returned answers

Before: d10. Topic: recursion.

Given: n in 0..10. Input: n.

F(0)=0, F(1)=1; combine the two returned Fibonacci values.

Sample input (w08_sample.txt):

6

Expected output:

fib=8

FIBs: code completion

b1 — An independent string copy

Before: w01 w02 d03. Topic: allocation.

Given: One word, 1..30 ASCII letters. Input: word.

Complete copy_word: return independently allocated, terminated storage containing source; return NULL on failure. strcpy is allowed. Driver changes source after copying.

Sample input (b1_sample.txt):

lab

Expected output:

source=#ab copy=lab

b2 — Resize without losing ownership

Before: d04 w01 w02 w03 w04. Topic: allocation.

Given: old_n in 1..10, new_n in old_n+1..20, fill in -100..100; then old_n ints in -100..100. Input: old_n new_n fill values.

grow returns the resized array with preserved old values and added elements equal to fill. On failure return NULL and leave the original allocation valid; the caller frees it. Use realloc.

Sample input (b2_sample.txt):

2 4 5 7 2

Expected output:

values: 7 2 5 5

b3 — Recursive digit sum

Before: w05 w06. Topic: recursion.

Given: n in 0..999999. Input: n.

Return the sum of decimal digits recursively, including n=0. Use recursion, not loops.

Sample input (b3_sample.txt):

2040

Expected output:

digit-sum=6

b4 — Count matches recursively

Before: w06 w07. Topic: recursion.

Given: n in 0..20, target in -5..5; then n ints in -5..5. Input: n target values.

Return the number of target occurrences among the first n elements. Use recursion, not loops.

Sample input (b4_sample.txt):

5 2 2 1 2 3 2

Expected output:

count=3

Exercises: complete functions

e1 — Filter readings into a new array

Before: w01 w02 w03 w04 b1. Topic: allocation.

Given: n in 1..20, threshold in -100..100; then n ints in -100..100. Input: n threshold values.

Write filter. Retain values >= threshold in original order, without changing a. Return a separately allocated array and write its count through out_count. For no matches return NULL and set count=0. On allocation failure return NULL and set count=-1. Caller owns and frees the result. No static result array.

Sample input (e1_sample.txt):

5 3 1 3 5 2 3

Expected output:

count=3 values: 3 5 3

e2 — Append records and find the best

Before: b2 w04. Topic: allocation.

Given: n and m in 1..10; then n first-batch records and m second-batch records, each id value. IDs are unique integers in 1..1000; values in -100..100. Input: n m records.

Write join_readings and best_index. join_readings must malloc space for the first batch, copy it, realloc for both batches, and append the second batch in order. Return NULL on either failure and release anything allocated inside the function. Do not change inputs. Caller frees successful result. best_index returns the zero-based index of the largest value; ties keep the earliest record.

Sample input (e2_sample.txt):

2 2 11 7 22 9 33 9 44 2

Expected output:

records: 11:7 22:9 33:9 44:2
best=22 value=9

e3 — Recursive palindrome

Before: b3 b4. Topic: recursion.

Given: One word, 1..30 ASCII letters. Comparison is case-sensitive. Input: word.

Write palindrome(s,left,right) for the inclusive range. Return 1 for a palindrome, otherwise 0. A range with left>=right is a palindrome. Compare ends and recurse inward; no loops, reversal library or string copy inside this function. Do not change s.

Sample input (e3_sample.txt):

level

Expected output:

palindrome=1

e4 — Recursive first occurrence

Before: b4. Topic: recursion.

Given: n in 0..20, target in -5..5, start in 0..n; then n ints in -5..5. Input: n target start values.

Write first_index: return the smallest index i with start<=i<n and a[i]==target, or -1 if absent. Indices are zero-based. Use recursion, not loops; stop before accessing a[n]. Do not change a.

Sample input (e4_sample.txt):

6 2 1 2 4 2 2 1 2

Expected output:

index=2

Check and submit

./check.sh

Each program is checked against four public cases and eight fresh random cases from its GIVEN. PUBLIC-CASES.txt lists the public cases. The checker compares the whole output, ignoring whitespace differences, and requires successful termination. Extra prompts and debug messages fail. Random tests prevent memorising the sample.

Partial credit is awarded per case, then each problem’s mark is rounded to the nearest whole mark (half rounds up). The displayed total can vary as random cases change. Eighty marks come from programs; twenty come from explaining your own code and reviewing ownership/cleanup and recursive implementation. Output alone cannot prove these properties.

When done, type exit to stop the recording shell, then bundle from your workspace:

./check.sh --bundle

This bundles partial work too. Keep TEAM.txt and session.txt. The archive is written above your workspace, named lab10_<rolls>_<branch>_w13.tar.gz for this week. Upload it as directed by the instructor and keep a copy outside the lab machine.

Before you leave

Be ready to explain both an allocation problem and a recursion problem:

  • Who owns each allocation, and what happens if resizing fails?
  • How is a copied string different from a copied pointer?
  • What are the base case, progressing argument and returned value in your function?
  • What happens for no matches, a singleton, or a search starting at the end?

If you finish early

Unmarked extensions: compare the call counts of recursive and iterative Fibonacci; then explain how you would append a third batch to E2 without losing the existing records on allocation failure. Keep your submitted solutions within their original contracts.
