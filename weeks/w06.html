W06: Making Decisions

Dates: Mon Sep 7 & Tue Sep 8, 2026 · 8:00–8:50 am · 12LH3004

Syllabus module: 4 — Control structures: boolean expressions, selection control (5 h)

In Class

Monday — selection, and the two words that leave a construct:

  • if, if/else, and the else-if ladder
  • switch, and why it needs break
  • break and continue inside the loops you already know
  • Lec 7 · Lec 8 — companion slides
ImportantThe sentence to leave with

break leaves exactly one construct — the nearest enclosing loop or switch.

Nearly everything that goes wrong this week is that sentence, not yet believed.

Code You Can Copy

Every program below was compiled and run before it was put here; the outputs are what they actually printed. Predict each one before you run it — that is the exercise; the typing is not.

1 · One decision, then two — if / else

#include <stdio.h>

int main(void) {
    int n;
    printf("Enter an integer: ");
    scanf("%d", &n);

    if (n % 2 == 0) printf("%d is even\n", n);
    else            printf("%d is odd\n", n);

    return 0;
}
7   ->  7 is odd
-4  ->  -4 is even

Note the test is n % 2 == 0, not n % 2 == 1. For -5, C gives -5 % 2 == -1 — so a program that asks “is the remainder 1?” quietly calls every negative odd number even. Lab 03’s drill 02 warned you.

2 · Many decisions in order — the else-if ladder

#include <stdio.h>

int main(void) {
    int age, price;
    printf("Enter age: ");
    scanf("%d", &age);

    if      (age < 5)  price = 0;
    else if (age < 18) price = 60;
    else if (age < 60) price = 150;
    else               price = 80;

    printf("price=%d\n", price);
    return 0;
}
3   ->  price=0        12  ->  price=60
30  ->  price=150      70  ->  price=80

The order of the rungs is the whole program. Each test is reached only when every test above it has already failed, which is why age < 18 does not need to also say age >= 5. Now swap the first two rungs and run it again: an 8-year-old pays 150.

Two questions to ask of any ladder: do my cases cover every possibility? and can two of them ever both be true?

3 · switch, where sharing a body is the point

#include <stdio.h>

int main(void) {
    char c;
    printf("Enter a lowercase letter: ");
    scanf(" %c", &c);          /* the space skips the leftover Enter */

    switch (c) {
        case 'a':
        case 'e':
        case 'i':
        case 'o':
        case 'u':
            printf("%c is a vowel\n", c);
            break;
        default:
            printf("%c is a consonant\n", c);
    }
    return 0;
}
e  ->  e is a vowel        k  ->  k is a consonant

A case with no statements simply falls into the next one. Five labels, one body. Here that is exactly what we want — remember this page when you meet the next one.

4 · The same mechanism, now a bug

#include <stdio.h>

int main(void) {
    int input;
    printf("Enter an integer: ");
    scanf("%d", &input);

    switch (input % 2) {
        case 0:  printf("Number is even\n");
        case 1:  printf("Number is odd\n");
        default: printf("Neither even nor odd\n");
    }
    return 0;
}
10  ->  Number is even
        Number is odd
        Neither even nor odd

5   ->  Number is odd
        Neither even nor odd

-5  ->  Neither even nor odd

Three lessons in one run. Without break, execution keeps falling through — 10 is even, odd, and neither. The entry point moves with the value, so 5 prints two lines. And -5 prints only the last line, because -5 % 2 is -1, which matches no case at all — that is why the default is there.

Add break; to the first two cases and run it again.

5 · switch on a character — the mini calculator

#include <stdio.h>

int main(void) {
    double a, b;
    char op;
    printf("Enter: a op b   (e.g. 6 * 7): ");
    scanf("%lf %c %lf", &a, &op, &b);

    switch (op) {
        case '+': printf("%g\n", a + b); break;
        case '-': printf("%g\n", a - b); break;
        case '*': printf("%g\n", a * b); break;
        case '/':
            if (b == 0) printf("cannot divide by zero\n");
            else        printf("%g\n", a / b);
            break;
        default:  printf("unknown operator '%c'\n", op);
    }
    return 0;
}
6 * 7   ->  42
10 / 4  ->  2.5
9 / 0   ->  cannot divide by zero
5 ^ 2   ->  unknown operator '^'

The / case carries an if inside it: dividing by zero is a precondition the operator cannot check for itself. And the default is what turns a typo into a message instead of silence.

Try it with int instead of double and ask for 10 / 4. You get 2. Week 3 is still collecting debts.

6 · break and continue in loops — is it prime?

#include <stdio.h>

int main(void) {
    int n, i, divisor;

    while (1) {                          /* keep going until told to stop */
        printf("Enter a number 2..99 (anything outside stops): ");
        scanf("%d", &n);
        if (n < 2 || n > 99) break;      /* leaves the WHILE */

        divisor = 0;
        for (i = 2; i * i <= n; i++) {
            if (n % i != 0) continue;    /* not a divisor - go to the next i */
            divisor = i;
            break;                       /* leaves the FOR, not the while */
        }

        if (divisor) printf("  %d is composite, smallest divisor %d\n", n, divisor);
        else         printf("  %d is prime\n", n);
    }
    printf("stopped\n");
    return 0;
}
97  ->  97 is prime
91  ->  91 is composite, smallest divisor 7
2   ->  2 is prime
-1  ->  stopped

Two breaks in one program, leaving two different loops. The first ends the whole session; the second ends only the divisor search. Neither reaches the other.

continue is the other word: it abandons this pass and goes to the next. Here it is only for illustration — if (n % i == 0) { ... } would do the same job — but it makes the shape visible.

Two things to try. Replace i * i <= n with i < n: still correct, and for 97 it takes 95 passes instead of 9. Then feed it 1, and decide whether the program’s answer is the one the specification wants.

7 · break to leave early — three attempts

#include <stdio.h>
#define PIN 4242

int main(void) {
    int entered, attempt, ok = 0;

    for (attempt = 1; attempt <= 3; attempt++) {
        printf("Enter PIN (attempt %d of 3): ", attempt);
        scanf("%d", &entered);
        if (entered == PIN) { ok = attempt; break; }
        printf("  wrong\n");
    }

    if (ok) printf("access granted on attempt %d\n", ok);
    else    printf("access denied after 3 attempts\n");
    return 0;
}
4242              ->  access granted on attempt 1
1111 2222 4242    ->  access granted on attempt 3
1 2 3             ->  access denied after 3 attempts

This loop can end for two different reasons — the right PIN, or running out of attempts. After the loop, the program still has to know which. That is the whole job of ok: a loop that forgets why it stopped cannot report what happened.

8 · The trap — break inside a switch inside a loop

#include <stdio.h>

int main(void) {
    double balance = 1000.0;
    int choice, pass = 0;

    while (pass < 3) {              /* bounded so we can watch the bug and still stop */
        pass++;
        printf("\n1 balance  2 deposit  3 withdraw  4 quit\nChoice: ");
        scanf("%d", &choice);

        switch (choice) {
            case 1: printf("balance = %.2f\n", balance); break;
            case 4: printf("quitting...\n"); break;      /* <-- leaves the SWITCH */
            default: printf("not implemented\n");
        }
    }
    printf("loop ended after %d passes\n", pass);
    return 0;
}

Choose 4 — quit — three times:

quitting...
quitting...
quitting...
loop ended after 3 passes

It never quits. The break did exactly what it promised: it left the nearest enclosing construct, and that was the switch. The while never heard about it.

The fix is not a cleverer break. It is to give the loop something of its own to look at:

#include <stdio.h>

int main(void) {
    double balance = 1000.0, amount;
    int choice, running = 1;

    while (running) {
        printf("\n1 balance  2 deposit  3 withdraw  4 quit\nChoice: ");
        if (scanf("%d", &choice) != 1) break;      /* input ran out */

        switch (choice) {
            case 1:
                printf("balance = %.2f\n", balance);
                break;
            case 2:
                printf("amount: "); scanf("%lf", &amount);
                balance += amount;
                printf("balance = %.2f\n", balance);
                break;
            case 3:
                printf("amount: "); scanf("%lf", &amount);
                if (amount > balance) printf("insufficient funds\n");
                else { balance -= amount; printf("balance = %.2f\n", balance); }
                break;
            case 4:
                running = 0;                       /* <-- this is what ends the LOOP */
                printf("goodbye\n");
                break;
            default:
                printf("no such option\n");
        }
    }
    return 0;
}
1               ->  balance = 1000.00
2, 500          ->  balance = 1500.00
3, 2000         ->  insufficient funds
4               ->  goodbye

After Class

  • Type and run all eight. Where the machine disagrees with your prediction, the disagreement is the lesson — find the rule you misapplied.
  • Break §4 further: add break to case 0 only. Now what does 5 print? And 10?
  • Break §2 on purpose: reorder the ladder so an 8-year-old is charged 150, and explain in one sentence why.
  • Extend §5: add % to the calculator. What must you change about the variables, and why does % refuse to work with double?
  • Extend §8: add a withdrawal limit of 500 per transaction. Which construct does that belong in — the switch, or an if inside the case?

Lab 05 is built on exactly this material. The drills there will catch you on §4 and §8 if you have not run them here first.
