Monday — Pointers

1 · A question you have already answered without knowing it

In W09 you wrote these two functions. They do the same arithmetic, but only one of them changes the caller’s variable:

#include <stdio.h>

void addOne(int n)        { n = n + 1; }
void reallyAddOne(int *n) { *n = *n + 1; }

int main(void)
{
    int x = 5;

    addOne(x);
    printf("after addOne(x),        x = %d\n", x);

    reallyAddOne(&x);
    printf("after reallyAddOne(&x), x = %d\n", x);
    return 0;
}
after addOne(x),        x = 5
after reallyAddOne(&x), x = 6

You have been using this since last week. The explanation then was “pass the address”. Today we say what an address is, what & and * actually do, and why this is the only way C can do it.

2 · Memory is numbered

A program’s memory is one long row of bytes, and every byte has a number. That number is called its address. The first byte is at some address, the next at that address plus one, and so on.

When you declare int x = 5;, the program sets aside enough adjacent bytes somewhere in that row to hold an int — four of them on the machines we use — and writes 5 into them. The variable name x is how you refer to those bytes. The address is how the machine refers to them.

Two things follow, and both matter:

  • Every variable has an address, because every variable occupies bytes.
  • An address is itself just a number, so it can be stored in a variable. A variable that stores an address is called a pointer.

If you print an address, you will get a different number every time you run the program. Modern operating systems deliberately place programs at different addresses on each run. So addresses are real, but no particular address is worth memorising, and no exercise in this course will ask you for one.

3 · Two operators

Operator Written What it gives you
address-of &x the address of the variable x
dereference *p the value stored at the address held in p

They undo each other. & turns a variable into an address; * turns an address back into the variable it refers to.

#include <stdio.h>
int main(void)
{
    int x = 5;
    int *p = &x;        /* p holds the address of x */

    printf("x  = %d\n", x);
    printf("*p = %d\n", *p);

    *p = 7;             /* write through the pointer */

    printf("after *p = 7, x = %d\n", x);
    return 0;
}
x  = 5
*p = 5
after *p = 7, x = 7

Read the last part carefully. *p = 7 never mentions x, and yet x changed. That is the whole point of a pointer: it gives a second route to the same storage.

*p can appear on either side of an assignment, and it means something different in each position. On the right, y = *p reads the value at that address. On the left, *p = 7 writes a value to that address.

4 · Declaring a pointer

int *p;

Read it as: *p is an int, therefore p is a pointer to an int.

The type matters. int *p may only hold the address of an int; char *s may only hold the address of a char. A pointer is not a general-purpose number — it carries the type of the thing it points at, and section 5 shows why that is more than bookkeeping.

The * belongs to the variable, not to the type. This line does not declare two pointers:

int *p, q;

p is a pointer to int. q is a plain int. If you want two pointers you must write the * twice:

int *p, *q;

This catches everyone once. Write one declaration per line and it cannot catch you at all.

5 · Adding 1 to a pointer moves it by one whole item

Adding 1 to a pointer does not move it one byte along. It moves it to the next item of that type.

#include <stdio.h>
int main(void)
{
    int a[5] = { 10, 20, 30, 40, 50 };
    int *p = a;

    printf("sizeof(int) = %zu\n", sizeof(int));
    printf("(p + 1) - p = %td        (counted in ints, not bytes)\n", (p + 1) - p);

    printf("a[2]        = %d\n", a[2]);
    printf("*(a + 2)    = %d\n", *(a + 2));
    printf("*(p + 2)    = %d\n", *(p + 2));
    return 0;
}
sizeof(int) = 4
(p + 1) - p = 1        (counted in ints, not bytes)
a[2]        = 30
*(a + 2)    = 30
*(p + 2)    = 30

Two facts here, and they are two halves of the same rule.

Going forwards, p + 1 is the address of the next int, which on this machine is four bytes further along, because sizeof(int) is 4. For a char *, p + 1 would be one byte further along. The compiler scales the step by the size of the type, which is why the type in the declaration is not decoration.

Going backwards, subtracting two pointers gives the number of items between them, not the number of bytes. That is why (p + 1) - p is 1 and not 4.

So pointer arithmetic is always counted in whole items of the pointed-to type. Nothing is stored in the pointer to make this happen; the compiler works it out from the type at compile time.

sizeof produces a value of type size_t, and %zu is the printf format for it. %td is the format for the result of subtracting two pointers. You can use them without studying either type further; just do not use %d for them.

6 · Arrays and pointers

The last three lines of that output are equal, and that is not a coincidence. In C, for any array a and index i:

a[i] means exactly *(a + i)

The subscript notation is a shorthand for pointer arithmetic. This is also the rule behind something you met in W09: when an array is passed to a function, the array name is converted to a pointer to its first element. That is why int a[] and int *a mean the same thing in a parameter list, and why the function can change the caller’s array.

7 · Why a function is usually told how long an array is

Here is the consequence, and it explains something you have been doing since you started writing functions over arrays:

#include <stdio.h>

void show(int a[], int n)
{
    printf("inside the function, sizeof(a) = %zu\n", sizeof a);
    printf("inside the function, n         = %d\n", n);
}

int main(void)
{
    int a[10];
    printf("in main, sizeof(a)             = %zu\n", sizeof a);
    show(a, 10);
    return 0;
}
in main, sizeof(a)             = 40
inside the function, sizeof(a) = 8
inside the function, n         = 10

In main, sizeof a is 40: ten integers of four bytes each. Inside the function it is 8, the size of a pointer on this machine.

The function was never given the array. It was given an address. The length did not travel with it, and there is no way to recover it from inside the function. That is why a function like

void minMax(int a[], int n, int *lo, int *hi)

has to take n as a separate parameter. You will meet this one in Lab 07.

The compiler knows this is a common mistake and warns about it. The exact wording differs between compilers; what matters is the file and line it points at:

warning: sizeof on array function parameter will return size of 'int *'
         instead of 'int[]' [-Wsizeof-array-argument]

This is about the first dimension only. A parameter written int world[ROWS][COLS], as in last week’s Game of Life, still carries its column count, because that number is part of the parameter’s type — it is what makes world[i][j] computable. That is why printWorld, countNeighbours and nextGeneration needed no length parameter: COLS was in the type and ROWS was a #define both sides could see.

What never survives is the number of rows, which is the dimension that decays to a pointer. So the rule is: a function is told the size of the dimension that decayed, and reads the rest from the type.

8 · What goes wrong

Four mistakes account for most pointer bugs. Three of the four are undefined behaviour, marked below. Read them; do not run them.

Declaring a pointer is not the same as giving it something to point at. (undefined behaviour)

int *p;      /* p exists, but has not been given an address */
*p = 5;      /* undefined: writes to an address nobody chose */

A pointer must be given an address before it is dereferenced, either from &something or from a function that returns one. Until then, as W09 §10 put it for arrays, what happens is undefined — not “whatever happened to be in that memory”. There is no value you can reason about, and reading it is itself undefined.

C gives you a way to say “not pointing at anything yet”. The name is NULL, and you can test for it:

#include <stdio.h>
int main(void)
{
    int x = 5;
    int *p = NULL;          /* NULL means: not pointing at anything yet */

    if (p == NULL)
        printf("p is NULL, so it must not be dereferenced\n");

    p = &x;                 /* now it points at something real */

    if (p != NULL)
        printf("p now points at x, and *p = %d\n", *p);

    printf("an address prints with %%p, like this: ");
    printf("%p\n", (void *)p);
    return 0;
}
p is NULL, so it must not be dereferenced
p now points at x, and *p = 5
an address prints with %p, like this: 0x16d4b32c8

The last line is the one from section 2 that changes on every run, so yours will show a different number. Note the two details: %p is the format for an address, and the pointer is cast to (void *) to use it. NULL returns in W13, where it is how malloc reports failure.

Confusing the pointer with the thing it points at. *p = 7 sets the variable p points at to 7. Writing p = 7 instead tries to set the pointer itself to the address 7, which is meaningless — and the compiler rejects it outright:

error: incompatible integer to pointer conversion assigning to 'int *' from 'int'

So that particular slip cannot get past the compiler. The dangerous version is the one where both sides are pointers: writing p = q when you meant *p = *q is perfectly legal, silent, and changes which variable p refers to instead of copying a value.

Returning the address of a local variable. (undefined behaviour) A local variable stops existing when its function returns, so its address refers to storage that has been given back. The pointer still holds a number, and the program may appear to work, which is exactly what makes it dangerous. You will see the proper way to return new storage when we reach malloc in W13.

Writing past the end of an array. (undefined behaviour) a[10] in an array of ten, or walking a pointer one step too far. C does not check this. We will come back to it on Tuesday, because the most common version in practice involves strings.

The three marked above are undefined behaviour: the C standard does not say what happens. The program may crash, may print nonsense, or may appear to work perfectly on your machine and fail on the examiner’s. Do not learn what your compiler happens to do with them. Learn not to write them.

8b · A worked problem: reversing a list in place

Everything from Monday, used once on a real task. The problem: reverse a list of readings in place, and report how many exchanges that took.

Three things make this need pointers, and each is one of the ideas above.

  1. swap has to change two variables belonging to its caller, so it takes their addresses.
  2. reverse has to modify the caller’s array, which it can, because an array argument is converted to a pointer.
  3. reverse has to hand back a count as well as doing its job, and a function can only return one value, so the count goes back through a pointer.
#include <stdio.h>

/* exchanges the two ints whose addresses it is given */
void swap(int *x, int *y)
{
    int t = *x;
    *x = *y;
    *y = t;
}

/* reverses a[0..n-1] in place, and reports how many swaps that took */
void reverse(int a[], int n, int *swaps)
{
    int lo = 0, hi = n - 1, count = 0;

    while (lo < hi) {
        swap(&a[lo], &a[hi]);
        count++;
        lo++;
        hi--;
    }
    *swaps = count;
}

void show(char label[], int a[], int n)
{
    printf("%s", label);
    for (int i = 0; i < n; i++)
        printf(" %d", a[i]);
    printf("\n");
}

int main(void)
{
    int a[7] = { 3, 1, 4, 1, 5, 9, 2 };
    int swaps;

    show("before:", a, 7);
    reverse(a, 7, &swaps);
    show("after: ", a, 7);
    printf("swaps made: %d\n", swaps);
    return 0;
}
before: 3 1 4 1 5 9 2
after:  2 9 5 1 4 1 3
swaps made: 3

Three points worth pausing on.

&a[lo] is the address of one element. a[lo] is a variable like any other, so & works on it. swap neither knows nor cares that its two addresses happen to be inside an array.

Seven elements, three swaps. The loop stops when lo and hi meet. With an odd count the middle element is never touched, because exchanging it with itself would achieve nothing.

reverse returns void and still produces two results — a changed array and a count. Both travel out through addresses. This is the shape you will use whenever one answer is not enough.

Check the loop condition. Writing lo <= hi instead of lo < hi would, for an odd-length list, swap the middle element with itself: harmless to the data, but the reported count would be wrong. A test that only looked at the array would never catch it.

Tuesday — Strings

9 · A string is an array of characters with a marker at the end

C has no separate string type. A string is an array of char in which the end of the text is marked by a character whose value is zero, written '\0' and called the null terminator.

char s[] = "level";

That declaration creates an array of six characters, not five:

index 0 1 2 3 4 5
character l e v e l \0

Every function that works on strings relies on that terminator being there, because nothing else tells it where the text stops. sizeof can tell you the size of an array wherever its declaration is visible, but section 7 showed that this does not survive being passed to a function — and a string function is almost always on the receiving end of that.

#include <stdio.h>
#include <string.h>
int main(void)
{
    char s[] = "level";

    printf("the characters are:");
    for (int i = 0; s[i] != '\0'; i++)
        printf(" %c", s[i]);
    printf("\n");

    printf("sizeof s  = %zu\n", sizeof s);
    printf("strlen(s) = %zu\n", strlen(s));
    return 0;
}
the characters are: l e v e l
sizeof s  = 6
strlen(s) = 5

10 · sizeof and strlen answer different questions

They differ here by exactly one, and it is worth being precise about why.

What it asks Answer for char s[] = "level"
sizeof s how many bytes were set aside 6, including the '\0'
strlen(s) how many characters before the '\0' 5

sizeof is answered by the compiler, which can see the declaration. strlen is answered at run time, by walking the array until it finds the terminator. And as section 7 established, sizeof gives the wrong answer entirely once the array has been passed to a function, whereas strlen keeps working, because it needs only the terminator.

11 · Writing strlen yourself, and a palindrome

Both of these are just the walk from section 9, with the loop doing different work.

#include <stdio.h>

int myStrlen(char s[])
{
    int n = 0;
    while (s[n] != '\0')
        n++;
    return n;
}

int isPalindrome(char s[], int n)
{
    int lo = 0, hi = n - 1;
    while (lo < hi) {
        if (s[lo] != s[hi])
            return 0;
        lo++;
        hi--;
    }
    return 1;
}

int main(void)
{
    char a[] = "level";
    char b[] = "lever";

    printf("myStrlen(\"level\") = %d\n", myStrlen(a));
    printf("\"level\" palindrome? %d\n", isPalindrome(a, myStrlen(a)));
    printf("\"lever\" palindrome? %d\n", isPalindrome(b, myStrlen(b)));
    return 0;
}
myStrlen("level") = 5
"level" palindrome? 1
"lever" palindrome? 0

isPalindrome uses two indices that move towards each other and stop when they meet. Note the loop condition is lo < hi, not lo <= hi: when they are equal they are on the same character, and a character always matches itself. A string of odd length has a middle character that is never compared, and does not need to be.

11b · Reading a string from the keyboard

Every string so far has been written into the program. To read one you type, use scanf with %s — and note that there is no &, because an array argument is already an address, which is section 6.

#include <stdio.h>
#include <string.h>
int main(void)
{
    char word[50];

    printf("Enter a word: ");
    if (scanf("%49s", word) != 1) {
        printf("no word was read\n");
        return 1;
    }

    printf("you typed \"%s\", which has %zu characters\n", word, strlen(word));
    return 0;
}

Typing level gives:

Enter a word: you typed "level", which has 5 characters

Two details that are not optional.

The 49 in %49s is a limit. The array holds 50 characters, one of which must be the '\0', so at most 49 may be read. Plain %s has no limit: type a longer word and scanf writes past the end of the array, which is the fourth mistake in section 8. Always give the number, and always make it one less than the array size.

%s stops at the first space. It reads one word, not a line. For "never odd or even" it would read only never. Reading a whole line needs a different tool, which we will not need before Lab 08.

12 · The library: string.h

Four functions cover most of what you need. All of them depend on the terminator being present.

What it does
strlen(s) number of characters before the '\0'
strcpy(dst, src) copies src into dst, terminator included
strcat(dst, src) appends src to the end of dst
strcmp(a, b) negative, zero, or positive, comparing character codes (see the warning below) 
#include <stdio.h>
#include <string.h>

void compare(char a[], char b[])
{
    int r = strcmp(a, b);

    printf("strcmp(\"%s\", \"%s\") is ", a, b);
    if (r < 0)       printf("negative: \"%s\" comes first\n", a);
    else if (r > 0)  printf("positive: \"%s\" comes first\n", b);
    else             printf("zero: they are equal\n");
}

int main(void)
{
    char a[20] = "hello";
    char b[20];

    strcpy(b, a);
    printf("b after strcpy(b, a)      = %s\n", b);

    strcat(b, " there");
    printf("b after strcat(b, \" there\") = %s\n", b);

    compare("abc", "abd");
    compare("abd", "abc");
    compare("abc", "abc");
    return 0;
}
b after strcpy(b, a)      = hello
b after strcat(b, " there") = hello there
strcmp("abc", "abd") is negative: "abc" comes first
strcmp("abd", "abc") is positive: "abc" comes first
strcmp("abc", "abc") is zero: they are equal

strcmp does not return true or false. It returns zero when the strings are equal, which is the opposite of what reading if (strcmp(a, b)) suggests. Write if (strcmp(a, b) == 0) when you mean “are these the same string”.

Only the sign of the result is defined. Do not depend on the particular number.

strcmp is not alphabetical order. It compares the characters by their numeric codes, and every capital letter has a smaller code than every lowercase letter — 'Z' is 90 and 'a' is 97. So:

strcmp("Zebra", "apple")  is negative:  "Zebra" comes first
strcmp("abc",   "ABD")    is positive:  "ABD"   comes first

For a dictionary ordering you would have to convert both strings to one case first. This is also why the After Class exercise has to say “ignore letter case” explicitly: comparing 'N' with 'n' finds them different.

strcpy and strcat do not check that the destination is big enough. If it is not, they write past the end of the array, which is undefined behaviour and one of the most exploited bugs in the history of software. Make sure the destination array has room, including one byte for the terminator.

13 · Two ways of writing a string, and they are not the same

char a[] = "hello";     /* an array of 6 chars, holding a copy of the text  */
char *p  = "hello";     /* a pointer to the text, which you must not modify */

The first makes an array and copies the characters into it. You may change them: a[0] = 'H' is fine.

The second stores the address of a string literal. String literals may be placed in read-only memory, and modifying one is undefined behaviour. p[0] = 'H' may crash, or may silently do nothing, or may appear to work. It is not a thing to try and find out; it is a thing not to write.

If you want a string you can modify, declare an array.

13b · A worked problem: palindromes in real sentences

Section 11 checked "level". Real text is not that tidy: "Never odd or even" is a palindrome, but only if you ignore the spaces and treat N and n as the same letter. This is the Tuesday problem, and it is the Monday problem with one change — compare instead of swap.

The two indices still start at the ends and move towards each other. What is new is that each one must first skip anything that is not a letter.

#include <stdio.h>

int myStrlen(char s[])
{
    int n = 0;
    while (s[n] != '\0')
        n++;
    return n;
}

int isLetter(char c)
{
    return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z');
}

char lower(char c)
{
    if (c >= 'A' && c <= 'Z')
        return c - 'A' + 'a';
    return c;
}

int isPalindrome(char s[])
{
    int lo = 0, hi = myStrlen(s) - 1;

    while (lo < hi) {
        while (lo < hi && !isLetter(s[lo])) lo++;
        while (lo < hi && !isLetter(s[hi])) hi--;

        if (lower(s[lo]) != lower(s[hi]))
            return 0;

        lo++;
        hi--;
    }
    return 1;
}

int main(void)
{
    char a[] = "level";
    char b[] = "lever";
    char c[] = "Never odd or even";
    char d[] = "A man, a plan, a canal: Panama";

    printf("\"%s\" -> %d\n", a, isPalindrome(a));
    printf("\"%s\" -> %d\n", b, isPalindrome(b));
    printf("\"%s\" -> %d\n", c, isPalindrome(c));
    printf("\"%s\" -> %d\n", d, isPalindrome(d));
    return 0;
}
"level" -> 1
"lever" -> 0
"Never odd or even" -> 1
"A man, a plan, a canal: Panama" -> 1

Four things to look at, because each one is a decision that could have gone wrong.

lower subtracts 'A' and adds 'a' rather than subtracting 32. Both work here, but the first says what it means: move this letter from the capital range into the small range. It also does not depend on you remembering that the gap is 32, which is the kind of thing the strcmp warning in section 12 was about.

The skipping loops carry lo < hi as well. Without it, a string with no letters at all would run lo off the end of the array — mistake four from section 8. Every loop that advances an index needs a reason to stop.

isLetter and lower are separate functions. Each does one thing and is three lines long. You could write the whole test as one enormous condition, and you would not be able to read it next week.

The structure is Monday’s. Two indices from the ends, moving towards each other, stopping when they meet. Monday exchanged the two elements; today it compares them. Recognising that one piece of machinery solves both problems is most of what this week is for.

This is the After Class exercise from section 11, worked. It is also close to what Lab 08 asks for, so understand it rather than copy it — the lab will not hand you the same sentence.

13c · Where this is going: linking things together

Pointers are not only a way to let a function change a variable. They are how C builds data structures that an array cannot give you, and the first of those is the linked list.

Here is the problem with an array. To insert a value in the middle, every element after it has to shift up one place to make room. For a thousand elements that is hundreds of moves for one insertion.

A linked list solves this by not storing the items next to each other. Each item keeps, alongside its value, where the next item is. To insert, you change two links and move nothing:

head → [10|•] → [20|•] → [30|✗]

insert 15 after 10:

head → [10|•] → [15|•] → [20|•] → [30|✗]
             ╰─ this link changed, and the new node points where it used to

You have not met the two tools C normally uses for this — struct, which arrives in W11, and malloc, in W13. But the idea needs neither, and you can run it today with what you already have. Keep the values in one array, and keep the links in a second array, where each entry is the index of the next item. -1 means “nothing follows”.

#include <stdio.h>

#define NONE -1

/* Insert v just after the node held in slot `at`, and return its slot.
   Nothing already in the arrays is moved. */
int insertAfter(int value[], int next[], int at, int v, int *used)
{
    int n = *used;

    value[n] = v;
    next[n]  = next[at];    /* the new node points where `at` used to point */
    next[at] = n;           /* and `at` now points at the new node          */

    *used = n + 1;
    return n;
}

void printList(int value[], int next[], int head)
{
    int i = head;

    while (i != NONE) {
        printf(" %d", value[i]);
        i = next[i];        /* follow the link */
    }
    printf("\n");
}

int main(void)
{
    int value[10], next[10];
    int used, head;

    value[0] = 10;  next[0] = 1;
    value[1] = 20;  next[1] = 2;
    value[2] = 30;  next[2] = NONE;
    head = 0;  used = 3;

    printf("list:          "); printList(value, next, head);

    insertAfter(value, next, 0, 15, &used);
    printf("15 after 10:   "); printList(value, next, head);

    insertAfter(value, next, 1, 25, &used);
    printf("25 after 20:   "); printList(value, next, head);

    printf("\nslot 1 still holds %d, slot 2 still holds %d — nothing was shifted\n",
           value[1], value[2]);
    return 0;
}
list:           10 20 30
15 after 10:    10 15 20 30
25 after 20:    10 15 20 25 30

slot 1 still holds 20, slot 2 still holds 30 — nothing was shifted

Two insertions into the middle, and not one existing value moved. That is the whole trade: an array gives you instant access to element i but expensive insertion; a linked list gives you cheap insertion but makes you walk from the front to find anything.

Notice what the program is made of. printList follows links until it reaches the end marker — the same shape as the strlen loop in section 11, which follows characters until it reaches '\0'. And insertAfter reports the new slot through int *used, because it has work to do and a value to hand back, which is section 8b.

What changes when you have the real tools. In W11 a struct will let one variable hold both the value and the link, so there are no parallel arrays. In W13, malloc will create nodes while the program runs, so there is no fixed-size pool and no used counter. The link stops being an index and becomes an actual pointer, and NONE becomes NULL:

struct node {
    int value;
    struct node *next;
};

for (struct node *p = head; p != NULL; p = p->next)
    printf(" %d", p->value);

That loop is printList above, written with the real tools. Compare them: i = next[i] has become p = p->next, and i != NONE has become p != NULL. Nothing else about the idea changed.

You are not expected to write that version yet. We build it properly in W14.
