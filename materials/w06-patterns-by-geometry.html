Patterns by Geometry

A pattern is not a pile of loops. It is a question you ask about a point — and once you see that, one program draws every shape.

The usual way to print a pattern is to work out, for each row, how many spaces come first and how many stars follow, and then get the arithmetic right. It works. It is also brittle: change the shape and every count changes, and nothing you learned from the triangle helps you with the diamond.

There is another way in, and it is worth the detour because it generalises.

1. A pattern is a question about a point

Stop thinking about rows of output. Think of the grid as a set of points (i, j), and of the pattern as a predicate — a yes/no question you ask about each one. Print a star where the answer is yes.

for (i = 0; i < n; i++) {
    for (j = 0; j < n; j++)
        putchar( ON_THE_SHAPE(i, j) ? '*' : ' ' );
    putchar('\n');
}

The loops never change again. Only the question does. Everything below is one line.

2. The border of a square

A cell is on the outer border when its distance to the nearest edge is zero:

min(i, j, n-1-i, n-1-j) == 0

and that generalises immediately. Ask for == k and you get the k-th ring in:

k = 0            k = 1            k = 2

One predicate, a family of pictures. Try writing that with space-counting.

3. The same square, said differently

Put the origin in the middle. Three names, and it is worth being exact about them:

symbolwhat it isrange
i, jwhere the cell is — row and column, counting from 00 … n-1
cthe midpoint index, (n-1)/2—
x = i - c
y = j - c		where the cell is measured from the middle-c … +c
rthe radius — how far out the shape sits0 … c

Note that c and r are different things that happen to be equal for the outer border: the centre is c steps from the edge, so the outermost ring has r = c. Keep them apart and the predicate gains a dial. The border is

max(|x|, |y|) == r        /* r == c for the outer border */

Verified: this draws the identical picture to §2 — cell for cell. Which is worth a moment, because it says the square is the set of points whose largest coordinate is r. That is a definition of a square you may not have met, and it is the one that travels.

4. Change max to + and you get a diamond

|x| + |y| == r

*       *

Nothing else moved. Same loops, same r, same grid — one operator. The square asked for the largest coordinate; the diamond asks for the sum. Those two questions have names, and you now know both: they are the L∞ and L1 distances. A shape is just a distance held constant.

5. The diamond is the square, rotated

Here is the part that should feel like a trick and is not. This identity is exactly true for every pair of integers:

|x| + |y|  ==  max( |x + y| , |x - y| )

I checked all 6 561 pairs with x and y from −40 to 40: zero failures. So the L1 question in (x, y) is the very same L∞ question asked in the coordinates (x+y, x-y) — which is a 45° rotation, with the usual 1/√2 simply dropped. We do not need it: we are not measuring, we are deciding which cells get a star.

So one predicate, two coordinate systems, two shapes:

max(|x|,     |y|    ) == r        max(|x+y|, |x-y|) == r

This is what people mean by exploiting the geometry. You did not write a diamond program. You wrote a square program and asked it a rotated question. The shape moved because the coordinates did.

6. And a circle, for the family portrait

Three shapes, three distances, one line changed each time. Here at n = 11:

   square                 diamond                 circle

Look closely at the circle. It is ragged, and no choice of predicate fixes that. A circle of radius c does not pass through whole numbers of cells, so any rule you pick — x*x + y*y == c*c catches almost nothing; a band like d <= c*c && d > (c-1)*(c-1) catches too much in the diagonals — is a decision, not a discovery.

Generalisation cost #1: not every shape fits the paper. The circle does not, and the moment a shape stops fitting, the program stops being a statement of fact and starts being a choice you have to defend. That is not a flaw in the method; it is the method telling you something true about circles and square paper.

And it is a scale, not a yes/no

Every picture above used an odd n. That was not laziness. Ask for an even one and the three shapes behave completely differently:

shapepredicatefits which grids?
squaremax(|x|,|y|) == revery n
diamond|x| + |y| == rodd n only
circlex*x + y*y ≈ r*rno n exactly

The diamond's failure is parity, and it is worth seeing. A diamond needs a single cell at its apex, which needs an exact centre cell — and an even grid has no centre cell, only a centre point between four of them. Push through anyway with c = (n-1)/2 and integer division quietly rounds down: at n = 8 you get a perfectly good 7×7 shape parked in the corner, with the last row and column blank. The program does not complain, because nothing is wrong with it. The request was impossible.

If you re-centre exactly using doubled coordinates — x = 2*i-(n-1), y = 2*j-(n-1), which puts the origin between cells when it needs to be — the square works for every n, and the diamond comes out completely empty: with n even, every |x|+|y| is even while n-1 is odd, so no cell can ever satisfy it. Not approximately empty. Provably empty.

This is the most useful thing on the page. A predicate does not just draw a shape — it can tell you the shape you asked for does not exist on the paper you have. A space-counting program would have printed something and let you believe it.

7. What the elegance costs — and which cost you can actually remove

The predicate asks its question at every cell. It is natural to say so the elegant version is n² and the direct one is 2n — and that is too loose, because three different things are being counted and they do not behave the same way. Separating them is the whole lesson.

The costpredicatedirect construction
deciding — times you evaluate a testn²n — one per row
calling — putchar/printf invocationsn²4n, printing runs with %*s
describing — characters onto the screenn²≈¾n²

The direct version, for reference. Instead of asking every cell are you on the diamond?, it asks each row which two cells are? — and the answer is arithmetic:

for (i = 0; i < n; i++) {
    int h = (i < n-1-i) ? i : n-1-i;      /* how far this row reaches out */
    for (j = 0; j < n; j++)
        putchar( (j == c-h || j == c+h) ? '*' : ' ' );
    putchar('\n');
}

Verified cell for cell against the predicate of §4, for every odd n from 3 to 101. Two corrections fall out of the table above, and both matter.

The deciding collapses to n, not 2n. One h = min(i, n-1-i) per row settles both stars, so there are n decisions and 2n stars. Those are different quantities, and the smaller one is the achievement: the positions are computed, not found. No search, no scan — arithmetic. That is exactly what it means to exploit the geometry.

The describing does not collapse at all. You cannot print a hole. To put a star in column 7 of a text stream you must first emit seven somethings, and blanks are the only somethings available. The grid has n² cells and almost all of them must be written whatever your algorithm knows.

How much can you shave off it? Only the trailing blanks, after the rightmost star. The leading blanks are how you reach the left star, and the middle ones hold the two apart — both are load-bearing. That gets you from n²+n down to about ¾n²: 788 994 bytes instead of 1 051 650 at n = 1025. A constant factor, not a better exponent. There is no n²/2 available, and no 2n at all.

8. Unless you stop printing a grid

The quadratic is not a fact about diamonds. It is a fact about rendering a grid as a stream of characters. Change the output format and it goes away: a terminal will accept an instruction to move before it prints, so you can address the 2n stars directly and never mention a blank.

/* "\033[;H" puts the cursor there; then one star.       */
printf("\033[2J");                                  /* clear once */
for (i = 0; i < n; i++) {
    int h = (i < n-1-i) ? i : n-1-i;
    printf("\033[%d;%dH*", i+1, mid-h+1);
    if (h) printf("\033[%d;%dH*", i+1, mid+h+1);
}
nbytes, full gridbytes, cursor movessaving
331 1225462.1×
12916 7702 3927.0×
10251 051 65022 20647.4×

That is about 22n bytes — linear, give or take the digits in the coordinates. And notice it loses for small n: 116 bytes against 90 at n = 9, because each move instruction costs more than the handful of blanks it replaces. Measured, the crossover is at n = 15 — 222 bytes against 240. Below that, the blanks are cheaper than describing where not to put them.

The lesson, and it is a general one. A better algorithm removes the cost of deciding. It cannot touch the cost of describing — that one is set by the output format you agreed to. If the description is what is expensive, no cleverness inside the program will help you; you have to renegotiate the format. Which is why make it faster is never a well-posed request until someone says which of the three costs is the problem.

9. The real lesson, and it is on your syllabus

Those two columns have names you will see again in this course: declarative and imperative. The syllabus lists them as a topic; this page is what the distinction actually feels like, in eleven lines of C, on a problem you can see.

Neither column is the right answer. Knowing which one you are writing — and why — is the skill.

A shape is a distance held constant. Change the distance and the shape changes. Change the coordinates and the shape rotates. Both are one line, and neither is a trick.

10. Try it yourself

  • Make the square filled instead of hollow. Which comparison changes, and to what?
  • Draw a hollow diamond (r = 2) inside a hollow square (r = 5) on one 11-wide grid, in one pass. How many predicates does that need — and does the order of the tests matter?
  • Predict, then check: what does |x| + |y| <= r draw? And max(|x|,|y|) <= r && |x| + |y| >= r?
  • The rotation used (x+y, x-y). What shape does (x+2*y, x-2*y) give, and why is it no longer symmetric?
  • Write the O(n) construction for the square border, the way §8 did for the diamond. Which rows need two stars, and which need n?
  • Run the diamond with n = 8 and explain, in one sentence, why the last row is blank — then say what the right answer to draw an 8-wide diamond actually is.
