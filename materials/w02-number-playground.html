“But typing 0.1 in Python prints 0.1 back — so is it stored exactly after all?”

No — and the explanation is worth keeping. What is stored is the nearest representable value (the impostor on the “exactly stored” line above). What is printed is a courtesy: modern languages compute the shortest decimal string that would decode back to exactly the same stored bits, and for that particular double the shortest such string happens to be “0.1”. Politeness, not honesty. The mask slips when arithmetic makes new bits: try 0.1 + 0.2 in any Python terminal → 0.30000000000000004 — the sum's bits are not 0.3's bits, so no short string exists. Or interrogate directly: format(0.1, '.20f') → 0.10000000000000000555. Even what a terminal prints is a representation choice — one more reader, one more convention.

Try this: encode 0.1 and read the “exactly stored” line — the machine keeps a rounded impostor, which is why C programmers never compare reals with ==. Then flip the sign bit of 6.5. Then flip one exponent bit and watch the value leap — exponent bits move worlds, fraction bits move whiskers.
